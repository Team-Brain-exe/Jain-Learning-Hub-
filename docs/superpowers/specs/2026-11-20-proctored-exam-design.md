# Proctored Exam Mode: Design

**Owner:** Ojush · **Reviewer:** frontend lead · **Date:** 20 Nov 2026
**Source tickets:** `OJUSH_TASKS_PHASE2.md` (P-0 to P-7 plus stretch), expanded to a full exam system.
**Mockups:** 7 screens approved on 20 Nov 2026 (`.superpowers/brainstorm/…/exam-screens.html`, not committed).

## 1. Intent

Course assessments today are a single scrolling page of 4–5 questions with no time limit. A course
that wants a proper final exam needs one that feels like a real exam: timed, one question at a
time, a question navigator, flag for review, a review screen before submitting, and basic
proctoring (fullscreen, tab-leaving, copy detection) that warns and logs.

The proctoring is a **deterrent, not security**. Everything runs in the browser against mock data.
The backend will later enforce the real timer and store the attempt. The front end is built so
those calls can be swapped in behind small functions.

## 2. Goals

All 40 items from the agreed feature list are in scope. Grouped:

- **Before:** an entry card on the quiz page that opens the exam in a **new tab**; a rules
  screen with the exam summary; an "I understand" checkbox; a system check (fullscreen support,
  screen size, single tab, storage available); a resume state.
- **During:**
  - Layout: one question at a time, a numbered navigator grouped by section (sidebar on
    desktop, bottom sheet on mobile), flag for review, clear answer, a progress bar.
  - Input: keyboard shortcuts.
  - Question types: single choice, multi-select, true/false.
- **Timer and saving:** a deadline-based countdown that survives refresh, tab close and laptop
  sleep; low-time states at 5 and 1 minutes; autosave of every answer with a "Saved ✓" indicator;
  an extra-time multiplier.
- **Proctoring:**
  - Fullscreen enforcement with a blocking overlay.
  - Detection of tab-hide, window blur, copy, paste and right-click, debounced to one violation
    per second.
  - Warning dialogs that Esc can't close; auto-submit after `maxViolations`.
  - A violation counter in the top bar; no text selection on question text.
- **Submitting:** a review screen listing unanswered and flagged questions; a confirmation dialog;
  auto-submit on timeout or violations that skips the "answer everything" rule.
- **After:**
  - Result card, correct/wrong/skipped breakdown and per-section scores.
  - Integrity summary and answer review with explanations.
  - ⚠ count on attempt-history rows.
- **Faculty/admin:**
  - Proctoring settings per quiz in the course builder.
  - Shuffling of questions and options per attempt.
  - A per-student violation timeline in `admin.tsx` (Ojush has taken this over from Manthan).
- **Quality:** keyboard and screen-reader support, focus kept inside dialogs, the edge cases in
  §8, `docs/proctoring.md`.

## 3. Non-goals

- No webcam, microphone, screen recording or face detection.
- No real server-side enforcement. That belongs to the backend developer; we only leave seams for it.
- No question types beyond single, multi and true/false (no free text or code answers).
- No per-question marks: every question is worth 1 mark.

## 4. Anti-goals (failure even if it "works")

- **A non-proctored quiz behaves differently in any way.** `/learn/<slug>/quiz` without `proctor`
  config must be byte-for-byte the same experience, and the existing tests stay unedited.
- **The UI or docs claim the proctoring is secure.** All copy says "recorded", never "prevented".
- **Restarting is an exploit.** Refreshing, closing the tab, opening a second tab or going back
  must never give a fresh timer or a fresh attempt.
- **A false positive ends an attempt unfairly.** One tab switch must count once, not twice, and
  iPhone (no Fullscreen API) must never be blocked.

## 5. Constraints

- **Stack:** React 19, TS, TanStack Router (file routes), Tailwind v4 tokens, shadcn components
  in `src/components/ui/*` (not editable), `lucide-react`, `sonner`, vitest.
- **Look:** Flowbite exam-style layouts, built **only** with existing shadcn pieces and
  `@/components/studio/ui` helpers. No Flowbite dependency and no hex colours.
- **Do not edit:** `src/routeTree.gen.ts` (regenerated by the router plugin), `src/components/ui/*`,
  existing tests, or `supabase/migrations` (Lovable-managed).
- **`src/data/platform.ts`:** optional fields plus the minimal scoring change in §7.2 only.
  Small PR, merged first, after a `git pull`.
- **`__root.tsx` belongs to Manthan:** it is not edited. The exam page covers the site header and
  footer itself (§6).
- **Workflow:** one ticket = one branch = one PR; no force-push (Lovable sync); lint, tests and
  build pass. Lint already fails on `main` for older files, so the PRs keep *their own* files clean.

## 6. Approach

**Chosen: a separate exam route, opened in a new tab.**

- `src/routes/learn.$slug.exam.tsx` gives the URL `/learn/<slug>/exam`. TanStack ranks the static
  `exam` segment above `$lessonId`, the same way `quiz` already works.
- The quiz page shows an entry card instead of questions when `quiz.proctor` is set. Its button is
  an `<a target="_blank" rel="noopener">` to the exam route.
- The exam page renders a shell of `fixed inset-0 z-50 overflow-auto bg-background`, which covers
  the header and footer without touching `__root.tsx`. In fullscreen, only the shell is visible.
- **Rejected:**
  - **Branching inside the quiz page:** it puts two unrelated layouts in one file and makes the
    header hard to hide.
  - **A separate `/exams` area:** it duplicates enrollment and attempt logic.

## 7. Data

### 7.1 `src/data/proctoring.ts` (new)

```ts
export type ViolationType = "tab_hidden" | "window_blur" | "fullscreen_exit"
  | "copy_paste" | "context_menu" | "fullscreen_unsupported" | "second_tab";
export interface Violation { type: ViolationType; at: string; counted: boolean }
export interface ProctorConfig {
  durationMinutes: number; maxViolations: number; requireFullscreen: boolean;
  shuffleQuestions?: boolean; shuffleOptions?: boolean;
}
export interface AttemptMeta {
  violations: Violation[]; timeTakenSec: number; autoSubmitted: boolean;
  autoSubmitReason?: "timeout" | "violations";
  sectionScores?: Record<string, { right: number; total: number }>;
  skipped?: number;
}
export interface ExamSession {            // one per `${slug}:${userId}`
  slug: string; userId: string; startedAt: string; deadlineMs: number;
  order: string[];                         // question ids in display order
  optionOrder: Record<string, number[]>;   // display index → original index
  answers: Record<string, number | number[]>; // ORIGINAL option indices
  flagged: string[]; current: number; violations: Violation[];
  tabId: string;                           // the tab that owns the session
}
```

- **Sessions store:** `examSessions = createStore<Record<string, ExamSession>>("jfet-exam-sessions-v1", () => ({}))`.
  It uses **localStorage** through `createStore`, which already wraps access in try/catch and syncs
  tabs through the `storage` event. `sessionStorage` (the ticket's suggestion) is per-tab, so closing
  the exam tab would reset the timer. That breaks the "restarting is an exploit" anti-goal.
- **Seam functions** (each marked with a `→ future endpoint` comment):
  - `startExam`
  - `saveAnswer`
  - `toggleFlag`
  - `recordViolation`
  - `finishExam`
  - `getActiveSession`
  - `finalizeExpired`
- **Pure helpers:**
  - `remainingSeconds(deadlineMs, now)`
  - `scoreExam(quiz, answers)`, which returns right, wrong, skipped and per-section scores
  - `shuffle(seed)`, deterministic per session
  - `effectiveMinutes(config, multiplier)`

### 7.2 `src/data/platform.ts` (tiny PR, merged first)

- `QuizQuestion` gains optional `type?: "single" | "multi" | "truefalse"`, `correctAll?: number[]`
  (multi only) and `section?: string`.
- `Quiz` gains optional `proctor?: ProctorConfig`.
- `QuizAttempt` gains optional `meta?: AttemptMeta`, and `answers` widens to
  `Record<string, number | number[]>`.
- `scoreQuiz` handles `type === "multi"` with an exact set match against `correctAll`. A question
  with no `type` scores exactly as today.
- `submitAttempt(user, slug, answers, meta?)` takes an optional 4th argument and stores it.
- **Multi questions in the builder** also keep `correct = correctAll[0]`, so the existing
  `validateSubmission` check (`options[correct]` not blank) keeps working unchanged.
- **Why the scoring change lives here:** certificates and `bestAttempt` read `attempt.score`, so there
  must be one scoring function. The backend will mirror it. **Flag this to the lead in the PR,** since it
  goes slightly beyond "optional fields only".

### 7.3 Sample data (`src/data/quizzes.ts`)

- **DSA quiz becomes the demo exam:** 10 questions in "A · Basics" and "B · Applied", including at
  least one multi and one true/false question, with
  `proctor: { durationMinutes: 2, maxViolations: 3, requireFullscreen: true, shuffleQuestions: true, shuffleOptions: true }`.
- **Python quiz stays non-proctored,** as the "unchanged" control.

### 7.4 Extra-time multiplier

`AppUser` gets an optional `timeMultiplier?: number` (default 1), seeded as 1.5 for one demo
learner. `effectiveMinutes = durationMinutes × multiplier`.

## 8. Behaviour

### 8.1 Session lifecycle (`useExamSession`)

- **Phases:** `intro → active → reviewing ⇄ active → finished`.
- **Start:**
  - `startExam` builds `order`/`optionOrder` (shuffled when configured) and sets
    `deadlineMs = now + effectiveMinutes`.
  - It then requests fullscreen. This must happen in the click handler, because browsers only
    allow fullscreen from a user gesture.
- **Resume:** opening the route with an existing session skips the intro and goes straight to
  `active`. The fullscreen overlay asks the student to re-enter fullscreen, since the browser needs
  a click for that.
- **Expiry while away:** if `now > deadlineMs` when the exam or quiz page loads, `finalizeExpired`
  submits with reason `timeout`. The quiz page calls it too, so an abandoned exam is always closed
  out.
- **Finish:**
  - It runs exactly once and exits fullscreen.
  - It calls `submitAttempt(user, slug, answers, meta)` and deletes the session.
  - It shows the result in the same tab.
- **Attempts:**
  - A session counts as an attempt only when it finishes.
  - Starting is blocked when `left <= 0`.
  - Resuming an existing session is always allowed.

### 8.2 Timer (`useCountdown`)

- Computed from the deadline every 250 ms and never decremented, so laptop sleep and background
  tabs can't stretch it.
- Below 5 minutes it uses warning styling; below 1 minute, destructive styling.
- An `aria-live="polite"` region announces only at 10, 5 and 1 minutes left.
- `onExpire` fires exactly once.

### 8.3 Proctoring (`useFullscreen`, `useViolationDetection`)

- **Counted violations:** `visibilitychange→hidden`, `blur`, `fullscreenchange` exit, `copy`,
  `paste`, `cut` and `contextmenu`. Any violation within 1 second of the previous counted one is
  ignored, so one tab switch fires once even though it triggers both hidden and blur.
- **Fullscreen overlay:** exiting fullscreen shows the blocking overlay. The questions are hidden
  and the timer keeps running.
- **No Fullscreen API (iPhone):** warn-only mode. One uncounted `fullscreen_unsupported` entry is
  logged and the student is never blocked.
- **Warnings:** each counted violation opens the `ViolationWarning` `AlertDialog`. It ignores Esc,
  keeps focus inside, and its only action is **I understand**. When the student is on their last
  warning, the wording is stronger.
- **Auto-submit:** reaching `maxViolations` finishes the exam with reason `violations` and skips
  the warning.
- **Second tab:** each tab gets a `tabId`. A tab opening a session owned by another live tab sees
  "This exam is open in another tab" with a **Use this tab** button. The takeover records an
  uncounted `second_tab` entry and the old tab shows the same blocker. Liveness is a heartbeat
  timestamp on the session, written every 5 seconds.
- **Text selection:** `select-none` on question text only, not on the options or the page.

### 8.4 Navigation and answering

- One question per screen.
- **Desktop navigator (≥ lg):** a right-hand sidebar grouped by `section`, with four states:
  answered (success), unanswered (outline), flagged (warning ring with ⚑), current (primary).
- **Mobile navigator:** a shadcn `Sheet` (bottom) opened from a "7 / 20" button. The sheet also
  holds "Review & submit".
- **Keyboard shortcuts (ignored while a dialog is open):**
  - `1`–`9` picks an option (toggles it on multi questions).
  - `←`/`→` move between questions.
  - `F` flags the current question.
- **Autosave:**
  - Every change calls `saveAnswer` and the top bar shows "Saving…" then "Saved ✓".
  - If storage throws, it shows "Not saved: don't close this tab" in warning styling. The
    in-memory answers still submit.
- **Clear answer** removes the stored answer.

### 8.5 Review and submit

- **Submit** from the top bar or the sheet opens the review screen: answered, unanswered and flagged
  counts, plus a "Needs attention" list with **Go →** links.
- **Submit exam** opens the shadcn `AlertDialog` "Submit exam?". It names the unanswered count and
  offers **Keep working** or **Submit now**.
- Unanswered questions score as wrong and are reported as *skipped*.

### 8.6 Result

- **Result card:** score ring, pass/fail, certificate link when passed, **Review answers** and
  **Close tab**.
- **Breakdown:** correct/wrong/skipped, plus a per-section progress bar.
- **`IntegritySummary`:**
  - Shows time taken, warning count, who submitted and a violation list with times.
  - With no violations it says "No integrity issues recorded." in `text-success`.
  - Auto-submit reasons read "Auto-submitted (time ran out)" or "Auto-submitted (too many
    violations)".
- **Answer review:** the same one-at-a-time view, read-only, showing the student's answer, the
  correct answer and the explanation.
- **Quiz page:** attempt-history rows get a ⚠ N chip when `meta.violations` has counted entries.

### 8.7 Builder (`src/components/studio/Builder.tsx`, `QuizTab`)

- An "Exam mode" switch reveals duration, max violations, require fullscreen and the two shuffle
  toggles.
- With exam mode on, each question gets a type select (single / multi / true-false) and a section
  field. True/false fixes the options to `["True", "False"]`.
- With exam mode off, the builder looks exactly as it does today. Turning exam mode off converts
  multi questions back to single choice (keeping `correct`) and drops true/false locking, so the
  plain quiz page never receives a question type it can't render.

### 8.8 Admin (`src/routes/admin.tsx`)

- A "Proctored attempts" table with these columns: student, course, score, warnings,
  auto-submitted, date.
- Expanding a row shows its violation timeline.
